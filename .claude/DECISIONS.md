# Decisions

- **Expo Router + custom navbar**: Stack with `headerShown: false`; navigation chrome is our own `Navbar`/`BottomNav` so web and native look identical.
- **No native date/time picker**: date chips (next 10 days) + hourly slot grid instead of `@react-native-community/datetimepicker` (doesn't work on web). Slots less than 60 min from now are disabled.
- **Custom dropdown** (`SelectField`): bottom sheet on mobile, centered dialog on larger screens; no third-party picker.
- **Animations with RN `Animated`** (no Reanimated): `useNativeDriver` only off web. Animated values created with `useState(() => new Animated.Value(x))` to satisfy React Compiler lint.
- **Persistence behind `bookingsApi.ts`**: screens never touch AsyncStorage directly, so a backend can replace it without UI changes.
- **New bookings start as `confirmed`**; `in_progress`/`completed` are derived from slot time until a backend owns status.
- **WhatsApp ack = `wa.me` link to the business number** with a prefilled message; the success screen shows a chat-style preview.
- **Phone validation**: Indian 10-digit mobile (starts 6–9), `+91` prefix shown, stored normalized.
- **Web confirm dialogs** use `window.confirm` (Alert buttons don't work on web) via `utils/confirm.ts`.
- **Font**: Plus Jakarta Sans, one family name per weight (needed on Android).
- **Navbar links trimmed to Home/Services** (2026-09-27): About/Contact/My Bookings removed from the top nav to make room for a location pill + search bar. `NAV_ITEMS` (full list) is kept as-is and still drives `BottomNav`, so those pages stay reachable on mobile; `Navbar` filters its own `TOP_LINKS` from it rather than forking the data.
- **Avatar replaces "Book a Service" on every breakpoint, not just desktop** (2026-09-27): the old WhatsApp icon was mobile/tablet-only; since login/account needs to be reachable everywhere and the home hero (which held WhatsApp CTA copy) was removed, the avatar took over that slot uniformly. WhatsApp is still reachable via the bottom CTA on Home, Contact, and My Bookings' "Help" button.
- **Location is a static "Solapur" pill, not a picker** (2026-09-27): single-city app for now; revisit when multi-city support is needed.
- **Mock, on-device auth** (2026-09-27, see `features/auth.md`): no backend/OTP exists yet, so `NavAvatar`'s login is just a name + phone stored in AsyncStorage, mirroring the `bookingsApi.ts` pattern (`authApi.ts` + `AuthContext`) so it's a one-module swap when real auth exists.
- **Home page hero, stats and the numbered "how it works" cards removed, then hero reverted same day**: first tried replacing hero+stats+old-services-grid with a single top section (icon tiles + curvy roadmap). User feedback: the icon tiles looked bad and didn't show price/rating, and asked to revert the hero design (keeping stats removed). Net result — home page is now: **hero (restored, unchanged from original)** → **"Our services" full photo `ServiceCard` grid (restored)** → **"How it works" using `RoadmapSteps`** (kept — not what was complained about — but as its own centered section/card, not paired with a grid) → Why → Testimonials → CTA. **Stats strip stays removed.** Lesson: prefer the existing photo `ServiceCard` over new icon-only tiles for anything that needs to "specify service details" (price/rating).
- **`react-native-svg` added** (2026-09-27): only third-party graphics lib in the project; used solely by `RoadmapSteps` to draw the curvy connecting path (a decorative, non-critical element — safe to drop if the dependency ever becomes a problem). Survived the hero revert since it wasn't part of the complaint.
- **Hero photo mosaic settled as a plain 2×2 grid** (2026-09-27): went through a labeled 2×2 collage, then a rotated/overlapping free scatter, before the user shared a reference screenshot asking for a flat, evenly-gapped, individually-rounded 2×2 grid with no labels/badges/frame. That's the final design — see `changes/2026-09-27-hero-services-collage.md` for the full iteration.
- **Mock, on-device location** (2026-09-27, see `features/location.md`): same pattern as auth — `LocationContext` + `services/locationApi.ts`, AsyncStorage-backed, no geolocation. Replaced the static "Solapur" text pill with `components/LocationPill.tsx`, an interactive picker over a fixed `CITIES` list.
- **Mobile navbar: location moved into the single top row, second row dropped** (2026-09-27): the mobile navbar used to have a second row under the logo/avatar bar just for the location pill. Requested to move location into the top row instead (next to the avatar) — simpler and matches the pattern of everything else living in one bar.
- **Mobile hero simplified** (2026-09-27): heading, subtitle and `TrustBadges` are hidden on mobile (`!isMobile &&`) per explicit request, leaving only the eyebrow badge and search bar; hero `minHeight` on mobile dropped from 520 to 320 in the same change so the now-sparser hero doesn't leave a large empty gap. Desktop/tablet hero is untouched.
- **Monorepo, 3 Expo apps + 2 shared packages** (2026-09-28, user choice): customer/vendor/admin share types, pricing, statuses and the mock backend so a real API only needs to be written once.
- **Mock backend with a real-API-shaped surface** (2026-09-28; user: backend undecided, "stub now, wire later"): async `backend.<role>.<action>()` calls with latency + `ApiError`; per-app AsyncStorage; no cross-app state. Demo "simulate" buttons stand in for the missing other side.
- **Seeded, deterministic data** (mulberry32) so all three apps show consistent demo content; bump `DB_VERSION` to invalidate stored copies.
- **Money in whole rupees**: tax/commission rounded; GST 18% added on top; commission per category; vendor sees service amount − commission, customer total shown separately.
- **Vendor wallet** = online payouts owed − commission owed on cash jobs − settled/in-process payouts.
- **Admin roles** super_admin/operations/finance/support via `ROLE_PERMISSIONS`; pages gate on `can()`.
- **Vendor suggestions** ranked by distance, same-day workload, rating, availability, category.
- **Charts hand-built on react-native-svg** following the dataviz skill (validated 4-colour palette, single axis, table view, tooltips) — no chart library.
- **Customer auth = phone OTP**; the Google button is a demo that pre-fills the profile and still requires OTP.
- **Live theme tokens + remount** (2026-09-29): the codebase had ~670 static colour refs, so instead of threading a theme hook everywhere, tokens are mutable objects rewritten by `applyTheme`, sheets are lazy (`createStyles`), and `ThemeProvider` remounts its subtree (key = theme version). Trade-off: a theme switch resets local UI state under the provider (open sheets close); navigation/URL is kept.
- **Themes = accent (purple | dark blue) × mode (light | dark | system)**, per app, stored on-device. Dark chart palette validated separately; pastel category tints are light-only (`tintTile`).
- **Cart = one visit per service** (2026-09-29): problems are multi-selected on the service page into an on-device cart; checkout shares one slot + address and creates one booking per service (a vendor is per category). `Booking.items` lists every problem; `problemTypeId` stays the primary for older code. "Not sure" resolves to the inspection problem and is deduped.
- **Location = city | detected current location | saved address** (2026-09-29): two-line Zomato-style header. Reverse geocoding is native-only in expo-location, so web shows the pinned coordinate + nearest served city. Saving addresses needs login.
- **"Other / Not sure" is an inspection request, not a problem type** (2026-10-02): the booking keeps the customer's category and carries `inspection` (description, fee, quote, Q&A). One small state machine (pending → quoted → approved/declined, or no_work_needed) shared by all apps via `shared/inspection.ts`. The fee is billed unless an approved quote replaces it; nothing can be completed or paid online while the price is open.
- **Backend = Spring Boot modular monolith in `backend/`** (2026-10-02, stack chosen by the user): one package per module, no Kafka — transactional outbox + `@Scheduled` worker; Redis for OTP, rate limits and relaying live events between servers.
- **Snapshot sync instead of per-screen endpoints** (2026-10-02): screens read one `Database` snapshot, so the HTTP client fetches a role-scoped `GET /api/v1/sync` after each action and on live "changed" events. Keeps every screen unchanged; move to deltas/pagination when data grows.
- **Text ids kept as primary keys** so seed, mock and server share ids; the dev seed SQL is generated from `seed.ts` with dates relative to `now()`.
- **Geography as generated columns** from lat/lng (no Hibernate Spatial); matching uses PostGIS `ST_Distance`.
- **Minimal in-house STOMP client** in `http.ts` (React Native has no EventSource; avoids a dependency).
- **`backend.kind`** (`mock` | `http`) gates demo-only UI (simulate, reset demo data).
