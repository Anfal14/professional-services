# Backend (Spring Boot)

**Where:** `backend/` — Java 21, Spring Boot 3.5.16, Maven wrapper. Packages under `com.profecian`: auth, customers, vendors, catalog, settings, bookings (+ "Not sure" inspection), assignment, payments, payouts, reviews, complaints, notifications (+ outbox), live (WebSocket), files, sync, admin, analytics, pricing, common, config.

**Source of truth:** `packages/shared/src/mock.ts` (actions, checks, error messages), `types.ts`, `pricing.ts`, `status.ts`, `notify.ts` (`NotifyFor.java` is a line-by-line port — keep in sync), `seed.ts`.

## Key pieces
- `sync/SnapshotService` + `GET /api/v1/sync` → `Api.Database` (same shape as `Database`), scoped: anonymous (catalogue, settings, published reviews) / customer / vendor / admin (everything).
- `bookings/BookingCore`: `moveTo` (the single status-transition method: vendor = VENDOR_NEXT only, customer = cancel while canCustomerModify, admin = override), `reprice`, `commit` (booking + timeline + notifications/outbox in the caller's transaction; `LiveEvents` published after commit). `@Version` optimistic locking on bookings, vendors, customers, payouts, catalogue, settings.
- Checkout: `POST /api/v1/customer/checkout` — one booking per service, one transaction.
- Matching: `assignment/VendorMatcher` — PostGIS `ST_Distance` + same-day workload + rating + availability + category (the mock's score formula).
- Payments: `PaymentGateway` (sandbox with simulateFailure; Razorpay TODO). Gateway call happens outside DB transactions; `Idempotency-Key` on pay; signed webhook `/api/v1/payments/webhook/{provider}` (HMAC + event-id dedupe); `LedgerService` rows; cash collection.
- Notifications: `NotificationService.publish` writes in-app rows + `outbox` rows; `OutboxWorker` (@Scheduled, `FOR UPDATE SKIP LOCKED`, exponential backoff, dead after `max-attempts`) sends via `Providers` (push/WhatsApp/SMS stubs).
- Live: `LiveEvents` → Redis channel `profecian:live` → `LiveRelay` → STOMP `/user/queue/events`, `/topic/admin`, `/topic/public` (JWT in the CONNECT frame).
- Auth: OTP in Redis (rate limit, attempts; sandbox code 123456), JWT HS256 access (15 min) + rotating hashed refresh tokens, signup token for new numbers, bcrypt admins; `@PreAuthorize("hasAuthority('PERM_x')")` from ROLE_PERMISSIONS.
- Files: `StorageService` (local signed URLs / S3 presigned); DB stores keys; `FileRefs.attach` only accepts the caller's own uploads.
- Schema `db/migration/V1__schema.sql`; dev data `db/dev/V1000__dev_seed.sql` generated by `npm run backend:seed` (dates relative to `now()`).

## Frontend
`packages/shared/src/http.ts` `createHttpBackend` — same `Backend` type as the mock (typechecked): snapshot refresh after each action and on live events, token refresh, photo upload, tiny STOMP client. Apps pick it when `EXPO_PUBLIC_API_URL` is set; `backend.kind === 'mock'` gates demo-only buttons.

## Tests
Unit (pricing, wallet, status steps, formats) always run; `*IT` Testcontainers (checkout, assignment, payments/outbox) skip without Docker.

## Known gaps
Razorpay adapter; real push/WhatsApp/SMS providers; push-token registration endpoint; admin list endpoints are not used by the UI (it renders from the snapshot); the snapshot is a full re-fetch (fine at demo scale — paginate/delta later).
